# Dashboard Implementation Contract

Revision 5. Preserve existing design system, navigation, preview, and PT-BR tone. No visual redesign is required. This contract supplements 06 with exact orchestration and service boundaries.

## Services And Ownership

`drafts/draftRepository.ts` exports `DraftRepository` and `createDraftRepository(client)` using the existing Neon client (no second auth provider). Methods all return Promise<Result<T>>: `load(): ContentDraft`, `head(): DraftHead`, `mutate(input: DraftMutationInput): DraftMutationResult`, `prepare(input: PrepareInput): PublicationPreparation`, `publish(preparationId, token): PublishResult`. The generic notation describes Result data, not unwrapped return values. Method calls map exactly to 15 admin RPCs.

`ai/connections/connectionRepository.ts`: `create(id, tokenHash, label)`, `list()`, `revoke(id)` return Result<AgentConnection> or Result<AgentConnection[]>; `ai/files/exportRepository.ts`: `create(exportId, expectedGeneration, selection)` and `get(exportId)` return Result<EditExport>. Only these transports map snake_case parameters. Components consume interfaces, not Neon clients.

`drafts/saveCoordinator.ts` is a non-React service, `createSaveCoordinator({repository, cache, now, timers, onChange})`. Public methods: `load(principalId)`, `edit(candidate)`, `flush(): Promise<boolean>`, `refresh()`, `resolve(decisions)`, `retry()`, `discardLocal(): Promise<void>`, `dispose()`. `onChange(state)` receives the immutable state below. Inject clock/timers/repositories for tests; no module-global draft state.

```ts
interface SaveState {
  phase: 'loading' | 'clean' | 'dirty' | 'saving' | 'offline' | 'conflict' | 'error';
  base: (DraftHead & { payload: PublishedContentPayload }) | null;
  local: PublishedContentPayload | null;
  conflicts: SemanticConflict[];
  error: EditorialError | null;
  cacheAvailable: boolean;
}
```

`useDraftWorkspace` owns one coordinator per authenticated principal and disposes it on unmount/logout/principal change. Its V2 signature is `useDraftWorkspace(principalId: string)` and return shape `{state, edit, flush, refresh, resolve, retry, discardLocal}` (method signatures identical above). DashboardRoute adapts existing editor callbacks to candidate updates in INTEGRATION-02, not inside core validators. Existing published-content provider remains the public read source; it is not the draft source.

## State Transitions

| Event / state                                 | Required behavior                                                                                                                                                                                                                                                                                                             |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| load                                          | Load/initialize canonical draft, verify digest, then check principal-scoped recovery cache. Until ready disable editing/publish/export. Failure preserves cache, offers retry, never seeds bundle.                                                                                                                            |
| edit while clean/dirty/saving                 | Update local immediately; reset 750 ms trailing save timer but not initial 5-second maximum-wait deadline; cache at 250 ms. Never block typing during save.                                                                                                                                                                   |
| save timer or flush while dirty               | Snapshot base B and candidate C, encode B->C, keep exactly one request in flight. Zero operations -> clean without RPC.                                                                                                                                                                                                       |
| edit during save                              | Store latest local L separately from C. Do not mutate B/C captured by request.                                                                                                                                                                                                                                                |
| successful save of C (possibly merged into A) | Advance base to acknowledged A/head. Reconcile {base:C, local:L, remote:A} to carry edits made during request forward, rather than assigning C/A over L. If no later edits local=A. Incomplete rebase enters conflict, never drops remote fields. Schedule remaining delta immediately after one in-flight request completes. |
| stale_generation                              | Fetch remote R, reconcile {base:B, local:C, remote:R}; complete merge retries once using encode(R, merged). Preserve later L through C->merged rebase on acknowledgement.                                                                                                                                                     |
| second stale in same save cycle               | Enter conflict with retry_required, retaining original local/base and latest remote. Require explicit Review/Retry; no timer-driven loop.                                                                                                                                                                                     |
| unresolved semantic conflict                  | Keep B/local/R and fingerprinted decisions; autosave suspended. Manual conflict choices do not persist incomplete candidate.                                                                                                                                                                                                  |
| resolve                                       | Re-fetch head; if changed fetch remote and recompute conflicts, retaining only matching IDs. When all current conflicts resolved, conditional save against fetched remote. One automatic retry budget for this explicit action.                                                                                               |
| ambiguous network outcome                     | Read full remote. If sameContent(remote.payload, attempted candidate), acknowledge as saved at remote head; otherwise reconcile from original B. Never assume request rollback or blindly increment generation.                                                                                                               |
| offline / read recovery unavailable           | Preserve local/base. Mark offline if browser offline, otherwise error. Stop save timers; no network retry loop.                                                                                                                                                                                                               |
| online/focus                                  | Refresh head, reconcile dirty local then save when safe. Read failure keeps error/offline and local data.                                                                                                                                                                                                                     |
| explicit retry                                | New bounded save cycle after refresh. Never a force overwrite.                                                                                                                                                                                                                                                                |
| discard local                                 | Confirm with admin, fetch latest canonical, replace local/base, delete only current tab's recovery record. Does not delete or reset Neon draft.                                                                                                                                                                               |
| publish response                              | Refresh canonical draft and public publication query. Another editor's later changes may exist; never assume publish result is current head.                                                                                                                                                                                  |
| dispose/auth change                           | Cancel timers/listeners and ignore late UI callbacks with lifecycle epoch. Preserve unsynced principal cache. Do not send queued mutations under a different principal.                                                                                                                                                       |

An acknowledged base can be built from captured candidate/head, but persist its full verified canonicalPayload only after the next full draft read; recovery cache stores semantic base and server digest separately and does not fabricate canonical text. If that refresh reveals a later generation, reconcile normally. An inability to refresh after success cannot turn a known successful save into a failed mutation.

Polling: while visible, one head check every 15 seconds, no overlapping reads; hidden stops polling. Focus/online immediate head check. Head unchanged -> no payload fetch. When clean adopt verified newer remote. When dirty/saving queue one refresh and run after current mutation finishes. No BroadcastChannel protocol or real-time subscriptions.

Exact save labels: dirty `Alterações pendentes`; saving `Salvando...`; clean `Salvo no BemTeVi`; offline with successful cache `Sem conexão. Salvo neste dispositivo`; conflict `Conflito: revise as alterações`; error `Não foi possível salvar`. If cache fails never claim locally saved: `Alterações apenas nesta aba. Baixe uma cópia antes de sair.` Keep download recovery action and beforeunload warning while dirty/offline/error/conflict/saving.

## IndexedDB Recovery

New database `bemtevi-editor-v2`, version 1, object store `recovery`, keyPath `key`. Record `{key, principalId, tabId, savedAt, baseGeneration, baseDigest, basePayload, localPayload}`; key `${principalId}:${tabId}`. tabId is random UUID kept in sessionStorage key `bemtevi:editor-v2:tab-id`. No capability/preparation tokens. Admin-only storage is an explicit exception to the end-user privacy rule; no educator session data.

Each tab writes only its own record; list only current principal's records. Resume own dirty record through reconciliation. Other-tab records are offered as recoverable copies with timestamp, never automatically merged or deleted. Clean record may be removed only after acknowledged save; if new edits arrived while saving, replace it with updated base/local instead. IndexedDB failure leaves memory intact and cacheAvailable=false.

One-time legacy recovery: retain original localStorage/IndexedDB bytes. Read existing workspace and draftDb formats through a read-only adapter; offer explicit import of one selected legacy workspace. With basePayload use existing merge against current Neon draft; without base, permit download only, no inferred base or overwrite. Successful legacy import is still normal conditional save; mark its source ID as offered in new store only after acknowledgement. Do not treat previous local generations as Neon generations. Existing undo/checkpoints are local recovery artifacts: choosing a checkpoint creates a new candidate relative to current base, never decrements generation or restores a separate canonical workspace. Limit active in-memory undo to 20 candidates; don't upload history snapshots to Neon.

## Publication And File Actions

Publish/export/import first await flush; false/offline/conflict/error cancels the action. Capture clean generation; disable local editing while publish confirmation is open. Validate exact canonical snapshot with core, show diff versus live, require explicit `Publicar` click. Prepare with new UUID/token hash, then publish same preparation. Re-check generation and live revision before prepare. Any change after preview closes confirmation and requires a fresh review. Client failures never fall back to direct table UPDATE. Clear raw preparation token on dialog close/logout/success. A lost publish response may replay same preparation/token once; UI then refreshes.

Connection UI appears after file UI, uses metadata service, allows all-admin listing/revocation and self-attributed creation, and clearly states one-year nonrenewable delegated edit/publication authority. Generate secret only on Create, show once with copy/download, never regenerate when rerendering. Lost create result is retried with same UUID/hash. No publish toggle. Revoke requires explicit confirmation; disable actions while pending; stale list refresh after completion.

File export uses server-captured full base after flush, never current unsaved React state. Selected resource means selection of that material ID; no selection means whole corpus. Import contract is 14; parse/resolve images/validate on base before touching React local state. Show diff and semantic issues; Apply is explicit. Import conflict resolution uses same coordinator, no AI shadow draft. Export expiry message tells user to export again, not to rewrite IDs in the returned file.

## Payload Cost Budget

Live audited payload is 2,232,870 compact UTF-8 bytes (revision 50); fallback 2,208,625 bytes (revision 40). Full upload on every 750 ms save would be roughly 2.98 MB/second during sustained saves, before responses. Send field-level item patches; title-only edits must not include unchanged image/body bytes. A body-array replacement can resend images contained in that body; this is an explicit V2 tradeoff, not a general arbitrary JSON-path patch feature. Success/head responses contain no payload/canonicalPayload. Initial load, remote-generation changes, export capture and conflict recovery may transfer full payload. Do not run full read after every successful local save solely for display; verify when obtaining the next shared snapshot/recovery base.
