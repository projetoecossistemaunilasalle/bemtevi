## Inventory

**Migration 3 — `neon/migrations/20260910002000_content_agent_connections.sql` (~560 lines)**

- Private helpers (`content_private`, `SET search_path = ''`, UTC, fully qualified, no overloads/defaults, revoked from `public/anonymous/authenticated`):
  - `authenticate_agent(uuid, text) returns public.content_agent_connections` — the frozen verifier. Validates the 43-character canonical unpadded base64url token, decodes it to exactly 32 bytes, compares `sha256(decoded bytes)` (never the token text) with `token_hash`; locks the connection row `FOR UPDATE` (same lock serializes revocation: in-flight work may commit, every call starting after revoke completes fails); checks `expires_at <= clock_timestamp()`, `revoked_at`, draft binding (connection's draft row exists) and **current admin membership** of the delegating principal. Every missing/invalid/expired/revoked/wrong-secret/removed-principal case raises the single `invalid_capability` code. On success it updates `last_used_at` at most once per 15 minutes (throttled; a later domain failure still commits the stamp because domain errors are returned, never raised).
  - `decode_token_hash(text) returns bytea` — 64 lowercase hex only, decoded inside SQL; the raw capability secret never reaches the database as text.
  - `agent_connection_json` / `draft_json` / `edit_export_json` projections — camelCase wire shapes of doc 14; **no hash or secret column is ever exposed**; export projection returns `canonicalPayload = base_payload::text`.
  - `assert_export_selection(jsonb, jsonb)` — selection is JSON null or exactly `{scope, ids}` with 1..200 distinct nonempty IDs (≤200 code points) that exist in the draft payload; else `invalid_input`.
- Admin RPCs (granted to `authenticated` only):
  - `create_content_agent_connection(uuid, text, text)` — binds creation to self (principal from `auth.user_id()`, never request fields); requires an existing draft (`draft_unavailable`); idempotent replay of the caller-generated UUID succeeds only with same creator/hash/label/draft, otherwise `invalid_input`; server assigns `expires_at = now() + interval '1 year'` (calendar year).
  - `list_content_agent_connections()` — every admin lists every connection's metadata, sorted `created_at DESC, id ASC`; no hash column.
  - `revoke_content_agent_connection(uuid)` — any admin revokes any connection; missing ID → `invalid_input`; replay preserves the original `revoked_at`; rows retained for audit (no delete RPC).
- Durable exports (authenticated, creator-isolated):
  - `create_content_edit_export(uuid, bigint, jsonb)` — replay check first (same owner + generation + selection and unexpired returns the original export; otherwise `export_base_unavailable`); lock order exactly creator `admin_users` row `FOR UPDATE` → draft `FOR UPDATE` → published `FOR SHARE`; generation check under the draft lock (`stale_generation` + `currentHead`); captures full draft payload/digest/generation plus live published revision atomically; `expires_at = now() + interval '14 days'`; serial pruning under the creator lock: delete creator's expired rows, insert, then delete that creator's rows outside the newest five ordered `(created_at DESC, export_id DESC)` — concurrent creation by one admin cannot exceed the cap; other creators' rows untouched.
  - `get_content_edit_export(uuid)` — owner-only retrieval (even other admins get `export_base_unavailable`); expiry enforced on read even without pruning; missing/unauthorized → `export_base_unavailable`; null ID → `invalid_input`.
- Anonymous gateway wrappers (granted to `anonymous` only, capability-checked through the verifier): `agent_get_editor_context` (head + publishedRevision + principalUserId + connectionId + expiresAt), `agent_get_draft` (never initializes → `draft_unavailable`), `agent_get_published_content` (revision/payload/canonicalPayload/digest computed via `payload_digest`), `agent_apply_operations` (delegates to `content_private.mutate_draft(..., 'agent', principal, connection)`, so agent mutations carry connection attribution and the draft's admin/agent consistency check holds). Last_used_at commits even when the subsequent domain call fails.
- Privileges: all new functions revoked from `public/anonymous/authenticated`; admin wrappers → `authenticated` only; gateway wrappers → `anonymous` only; no broad role grants, no new table policies. List/get/reference MCP tools remain client projections — no SQL content-listing RPCs were created.
- Publication wrappers (`prepare_content_draft_publish`, `publish_content_draft`, `agent_prepare_publish`, `agent_publish_draft`) are intentionally **not** in this migration (DB-03 scope).

## Local SQL smoke (authoring aid, not a gate)

No `check:db` was run or faked. As with DB-01, the two prior migrations plus this migration were applied to a throwaway **Docker Postgres 17** container with stub `neon_auth."user"`/`auth.user_id()`/roles, then the RPC surface was exercised: init draft, connection create + idempotent replay + label mismatch, valid-token gateway context/draft/published/mutation (`lastActor` agent, generation 2), last_used_at stamping, revoke by another admin with replay-preserving timestamp, post-revoke `invalid_capability`, list metadata, export create/replay/stale-replay/bad-selection, foreign-admin denial, `digest = sha256(canonicalPayload)`, five-row pruning, expired export read (row retained), removed-principal/expired connections, and grant spot checks. The smoke caught one real defect **in the tests** (they initially hashed the token text; doc 15 requires hashing the decoded 32 bytes — `createHash('sha256').update(Buffer.from(token, 'base64url'))`) and confirmed the SQL was correct. The smoke also confirmed anonymous sessions get `permission denied` on direct table reads. The container was deleted after verification.

**Review finding (post-handoff):** independent review determined that the smoke-caught test defect described above was analyzed and documented but **not actually applied to `neon/tests/capabilities.test.ts`** — `newCapability()` still hashed the raw token text (`createHash('sha256').update(token, 'utf8')`) instead of the decoded 32 bytes. This has now been corrected in the file: the hash is `createHash('sha256').update(Buffer.from(token, 'base64url')).digest('hex')`, matching the SQL verifier. All other hashing sites in both test files were rechecked and are correct payload-text digests (`JSON.stringify(BASE_PAYLOAD)` and `data.canonicalPayload`), matching `content_private.payload_digest(jsonb)` semantics; no other file was modified.

## Notes / issues for downstream tasks

- The capability verifier raises (not returns) `invalid_capability`; wrappers catch it and return the Result error, so the throttled `last_used_at` update commits even when the subsequent domain call fails. Invalid authentication never reaches the update.
- Export replay is checked before taking locks; a replay with a mismatched generation returns `export_base_unavailable` (not `stale_generation`), matching the doc-15 replay rule.
- Pruning deletes the creator's expired rows and the rows outside the newest five, both serialized by the creator `admin_users` row lock; live tests must not shift `created_at` without also shifting `expires_at` (DB-01 table CHECK).
- `admin_users` has no `FOR UPDATE`-friendly RLS problem because the RPCs run as definer owner; the creator-row lock relies on the seeded membership row existing (DB-04 provisioning seeds A/B memberships).
- DB-03 adds the publication wrappers and must reuse `content_private.authenticate_agent` (lock order: connection → preparation → draft → published).
- No SQL RPCs were added for list/get-item/reference tools (client projections per doc 04/15).
