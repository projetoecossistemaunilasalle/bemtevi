## Defects found and fixed during implementation

- **D-1 (brief vs frozen SQL conflict — resolved in favor of the frozen contract):** the task text specified `tokenHash` = "lowercase hex SHA-256 of the raw token (`sha256Text`)" — i.e. hashing the 43-character base64url token TEXT. The frozen publication SQL (`content_private.publish_draft`) decodes `p_publish_token` to its 32 bytes and compares `pg_catalog.sha256(v_bytes)`, and DB-03's live test computes `sha256(Buffer.from(token, 'base64url'))`. Hashing the token text would make EVERY real publish fail `preparation_invalid`. Implemented: the handler generates 32 random bytes, encodes them to the 43-char base64url token, and hashes the SAME BYTES with content-core `sha256Bytes` (Web Crypto) — exactly matching the migration and the live test. The test verifies the equivalence explicitly.
- The task brief's seam notes suggested extending `src/tools/rpc.ts` with the publication calls; this was NOT done — `rpc.ts` is outside the MCP-03 ownership allowlist, and its existing exports (`fetchVerifiedDraft`, `fetchVerifiedPublication`, `rpcOnce`, `connectionArgs`) already cover every publication need. The `unavailable`→`published_base_unavailable` mapping and the publish replay live in the owned handler files.

## Notes

- A repeated `prepare_publish` tool call creates a NEW preparation each time (fresh UUID/token); only an internal transport replay with the same generated UUID would be idempotent server-side (doc 04 annotations note). The client never replays `agent_prepare_publish` on transport failure (no retry on the prepare RPC).
- The session cache is deliberately NOT cleared or special-cased by publication (doc 04 specifies nothing extra); publish_draft re-verifies nothing client-side beyond input shape — the database owns preparation binding/replay; the next `get_editor_context` re-verifies content.
- The raw publish token is returned ONLY in the prepare_publish result (`publishToken` field, the one allowed exposure per docs 04/14); it is never placed in any other RPC argument, log, or diagnostic (console-spy tests assert silence). Diagnostics continue to go through `redact()` upstream (MCP-01).
- File-budget status: production files ≤300 hard lines (preparePublish 232, publishDraft 101, definitions 217 — above the 200 soft target but within the hard ceiling, consistent with MCP-02's catalog precedent); tests ≤500 hard (publication.test.ts exactly 500, instructions.test.ts 97).
